# Paraguay Marangatu Tax Filing Automation

Playwright automation designed for Paraguayan tax residents who must file monthly zero-activity (no transactions) tax returns through Marangatu. It safely prepares and verifies Forms 120 and 241 for the previous calendar month.

For the taxpayer profile this repository was built for, completing these monthly zero-activity filings on time is an essential compliance step for maintaining the tax record used to support Paraguayan tax-residency status. Paraguay's DNIT requires registered taxpayers applying for a tax residence certificate to be current with their tax obligations. See [DNIT General Resolution No. 65/2020](https://www.dnit.gov.py/en/web/portal-institucional/w/resolucion-general-n-65-20).

> [!WARNING]
> This project is tailored to a specific zero-activity filing workflow. It does not establish tax residence by itself, determine whether you qualify for zero-activity returns, calculate taxes, validate amounts, or provide tax advice. Requirements vary by taxpayer. Real submission has legal consequences, so confirm your obligations, filing period, and form contents with Paraguay's tax authority or a qualified tax professional.

## Scope

The default filing period is always the previous calendar month, calculated in the `Europe/Madrid` time zone. The workflow:

- signs in to Marangatu;
- prepares Form 120 for obligation `211 - IVA General - MENSUAL`;
- prepares Form 241 through `Gestión de Comprobantes Informativos`;
- reaches the final actions without clicking them in dry-run mode;
- requires explicit period confirmation in real submission mode;
- verifies Form 120 in `Consultar Declaraciones` and Form 241 by confirming that no pending slips remain;
- saves local checkpoints and can send optional Telegram and Gmail notifications.

The automation does not enter, calculate, or correct tax data. It submits the content generated by the portal for the selected obligation and period.

## Safety controls

The default behavior is always `dry-run`. A real submission requires all three controls:

1. run the `submit` command;
2. confirm the exact period with `--confirm-period YYYY-MM`;
3. enable `MARANGATU_SUBMIT=true`, which the supervised launcher does only for that child process.

`--dry-run` and `--submit` are mutually exclusive. The monthly scheduled task never enables real submission, and the supervised launcher does not accept `--force`.

The automation does not bypass CAPTCHA, MFA, or any other portal control. Stop the workflow if one appears and complete it manually only when authorized.

## Requirements

- Node.js 20 or later.
- npm.
- Chromium installed through Playwright.
- Your own authorized Marangatu account.
- Windows to use the included Task Scheduler setup. Manual runs also work on WSL, Linux, and macOS.

The current workflow has been validated locally with Node.js 22.

## Installation

```bash
git clone https://github.com/jmgb/impuestos-paraguay-marangatu.git
cd impuestos-paraguay-marangatu
npm ci
npx playwright install chromium
cp .env.example .env
```

In PowerShell, replace the last command with:

```powershell
Copy-Item .env.example .env
```

At minimum, complete these variables in the private `.env` file:

```env
MARANGATU_USER=
MARANGATU_PASSWORD=
MARANGATU_HEADLESS=false
MARANGATU_SUBMIT=false
```

Never copy credentials or tokens into source code. `.env` is ignored by Git.

## Configuration

[.env.example](.env.example) contains the available project settings.

| Variable | Purpose | Default |
| --- | --- | --- |
| `MARANGATU_USER` | Marangatu username | Required |
| `MARANGATU_PASSWORD` | Marangatu password | Required |
| `MARANGATU_HEADLESS` | Run Chromium without a visible UI | `false` |
| `MARANGATU_SUBMIT` | Second interlock for real submission | `false` |
| `MARANGATU_SLOWMO_MS` | Delay between visible browser actions | `120` |
| `MARANGATU_EXPECTED_NAME` | Optional account-name verification text | Empty |
| `MARANGATU_ARTIFACTS_DIR` | Debug checkpoint directory | `artifacts` |
| `MARANGATU_PRESENTACIONES_DIR` | Local filing evidence directory | `presentaciones` |
| `MARANGATU_F241_GESTION_URL` | Optional fallback if portal navigation changes | Empty |
| `MARANGATU_TELEGRAM_ENABLED` | Telegram master switch | `false` |
| `MARANGATU_EMAIL_ENABLED` | Gmail master switch | `false` |

`MARANGATU_F241_GESTION_URL` must never contain a persisted session URL. The script first attempts to discover the dynamic route from the portal.

As an advanced option, `MARANGATU_PROJECT_ROOT` can be set in the process environment to point the launcher to another checkout. It is not read from `.env`, because it is used to locate the project itself.

## Usage

Run a visible dry-run for the previous month:

```bash
npm run dry-run
```

Run a dry-run for one form and an explicit period:

```bash
node src/marangatu.js --year 2026 --month 5 --dry-run --skip-f241
node src/marangatu.js --year 2026 --month 5 --dry-run --skip-f120
```

Validate real-submission interlocks without opening Marangatu:

```bash
npm run submit -- --confirm-period 2026-08 --check
```

Start a supervised real submission:

```bash
npm run submit -- --confirm-period 2026-08
```

Replace `2026-08` with the current previous-month period in Madrid. The launcher rejects any different period.

Run the deterministic test suite:

```bash
npm test
```

## Notifications

Email and Telegram are controlled independently and disabled by default.

### Telegram

```env
MARANGATU_TELEGRAM_ENABLED=true
MARANGATU_TELEGRAM_TOKEN=
MARANGATU_TELEGRAM_CHAT_ID=
MARANGATU_TELEGRAM_NOTIFY_DRY_RUN=false
```

When the master switch is enabled, Telegram reports real submissions and failed runs. Set `MARANGATU_TELEGRAM_NOTIFY_DRY_RUN=true` to also report successful dry-runs.

### Gmail

```env
MARANGATU_EMAIL_ENABLED=true
MARANGATU_GMAIL_FROM=
MARANGATU_GMAIL_TO=
```

Email is sent only after an error-free real run in which at least one newly filed form is verified. Dry-runs never send email. `.state/email-notifications.json` prevents duplicate messages for the same period.

OAuth credentials can be configured directly:

```env
MARANGATU_GMAIL_CLIENT_ID=
MARANGATU_GMAIL_CLIENT_SECRET=
MARANGATU_GMAIL_REFRESH_TOKEN=
```

Alternatively, they can be loaded from another private `.env` file:

```env
MARANGATU_GMAIL_CREDENTIALS_ENV=/absolute/path/to/private/.env
MARANGATU_GMAIL_REFRESH_TOKEN_ENV=GOOGLE_REFRESH_TOKEN
```

The external file must contain `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, and the refresh-token variable named above.

## Monthly scheduling

The included scheduler setup targets Windows Task Scheduler:

```powershell
npm.cmd run register-task
```

The task wakes at 12:00 and 12:30, while `scripts/run-monthly-check.ps1` runs Node only when Madrid time is between 12:00 and 12:59 on day 1. `.state/last-run.txt` prevents duplicate monthly runs.

Scheduled executions always use `--dry-run`. Real submission is never scheduled or retried automatically.

## Evidence and privacy

- `artifacts/` contains potentially sensitive screenshots and debug HTML.
- `presentaciones/YYYY-MM/` contains local evidence of real filings.
- `.state/forms.json` stores local state to prevent duplicate submissions.
- `.env`, `.state/`, `artifacts/`, and filing evidence are ignored by Git.

On Windows, remove debug checkpoints with:

```powershell
npm.cmd run clean:artifacts
```

Never publish screenshots, HTML, filing evidence, tax identifiers, credentials, or session URLs. See [SECURITY.md](SECURITY.md) to report a security issue or accidental exposure.

## Maintenance

Marangatu may change selectors, labels, or confirmation dialogs without notice. When that happens:

1. run only a dry-run;
2. inspect the latest checkpoint;
3. make the smallest possible selector fix;
4. run `npm test`;
5. repeat one supervised dry-run.

GitHub Actions runs deterministic tests and secret scanning. CI never signs in to Marangatu.
